# StarCraft II PPO Agent

A Gymnasium environment and PPO training loop for a Protoss StarCraft II bot.
The learner and the BurnySC2 game process communicate through a small,
process-safe request/response protocol so training logic stays separate from
the live game client.

The primary live runtime is Windows, where StarCraft II and the Python agent run
on the same machine. The protocol, environment contract, and strategy logic can
be developed and tested headlessly on Windows, macOS, or Linux without starting
the game.

## Architecture

```text
Stable Baselines3 PPO
        │
        ▼
Gymnasium environment
        │ action request
        ▼
atomic request file + episode/request ID
        │
        ▼
BurnySC2 Protoss bot ──► StarCraft II
        │
        └──────── observation, reward, and terminal response
                         │
                         ▼
                atomic response file
```

The IPC layer uses separate single-writer request and response files. Each
message includes episode and request identifiers, allowing the learner to
reject stale state. `SC2_RUNTIME_DIR` can be set to isolate concurrent runs.

## Environment contract

- **Observation:** `224 × 224 × 3` visual state.
- **Actions:** expand/mine, build Stargate, build Void Ray, scout, attack, and
  retreat.
- **Policy:** PPO through Stable Baselines3.
- **Bot:** Protoss economy and production logic built with BurnySC2.
- **Tracking:** optional Weights & Biases and TensorBoard logging.

The game-side implementation lives in
[`src/incredibot-sct.py`](src/incredibot-sct.py). The Gymnasium adapter and
reward lifecycle are in [`src/sc2env.py`](src/sc2env.py), and the shared IPC
contract is in [`src/ipc.py`](src/ipc.py).

## Supported workflows

| Workflow | Windows | macOS | Linux/WSL |
| --- | --- | --- | --- |
| Headless tests and linting | Supported | Supported | Supported |
| Live bot and PPO training | Primary path | Run inside a Windows VM | Experimental; depends on the local SC2 runtime |

The repository does not claim that CrossOver, Wine, WSL process bridging, or a
native Linux installation will behave like the Windows runtime. Use those paths
for experimentation, not as the baseline setup.

## Quick start for development

Prerequisites:

- Python 3.11 or 3.12;
- [uv](https://docs.astral.sh/uv/);
- a licensed StarCraft II installation for live runs; and
- compatible `.SC2Map` files for the selected scenario.

```bash
git clone https://github.com/T-Py-T/starcraft2-ppo-agent.git
cd starcraft2-ppo-agent
uv sync --locked --extra dev

make setup-maps
make check-env
```

Platform-specific setup is under [`run/`](run):

- [`run/windows/`](run/windows) for the supported native Windows setup;
- [`run/linux/`](run/linux) for experimental Linux or WSL setup; and
- [`run/macos/`](run/macos) for headless development and a Windows VM workflow.

If the game is installed in a non-default location, set `SC2PATH` or update the
path handling in [`src/config.py`](src/config.py).

## Windows live setup

From PowerShell, install the locked environment and prepare a genuine map:

```powershell
uv sync --locked --extra dev
Set-Location run/windows
.\download_maps_simple.ps1
uv run create_simple_map.py
Set-Location ../..
uv run python src/test_bot.py
```

`download_maps_simple.ps1` creates the expected directories; it does not create
a StarCraft II map. Place a genuine `Simple64.SC2Map` in the project `Maps`
directory first, or set `SC2_MAP_SOURCE` to an existing map archive. See the
complete [Windows guide](run/windows/README.md).

## Train and evaluate

Start PPO training:

```bash
make train
```

Run the game bot directly or evaluate a saved model:

```bash
make test-bot
make test-model
```

These commands launch the commercial game runtime and depend on local maps,
display settings, and model files. Model output, TensorBoard logs, and optional
Weights & Biases runs are stored outside the source modules.

## Game maps

Maps are runtime inputs and are not generated by this repository. Use a map
distributed with your StarCraft II installation or another map you are allowed
to use. Keep the original `.SC2Map` archive intact and point the setup helper at
it; renaming an unrelated ZIP file does not make it a valid map.

## Headless validation

The protocol and environment can be tested without launching StarCraft II:

```bash
make test
make lint
make type-check
```

The tests cover atomic publication, request and episode correlation, stale
message rejection, the fixed observation shape, terminal-state precedence,
and the initial ready handshake.

These checks exercise the agent boundary without a game installation. A live
Windows run remains the final validation for map discovery, game launch, and
in-game behavior.
